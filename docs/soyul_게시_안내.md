# soyul 통합·게시 안내

2026-11-18. 로컬 B 담당 작업과 원격 soyul(`1a3dc8e`)의 팀원 변경을 합쳤다. main 브랜치에는 커밋하거나 푸시하지 않는다.

## 포함된 작업

- J/P 진단 저장·결과 처리, 실제 여행 동행자 조회/내보내기, 일정 배분·저장 충돌 검사.
- 시흥 맛집/카페 각 20개 후보, 필터와 추천 미리보기·일정 반영.
- 이메일 로그인/가입, 익명 계정 연결, 1회용 초대, 로그아웃·계정별 최근 여행 복원.
- 팀원의 달력 입력, 랜딩 디자인, 숙소·교통 입력, 프로필/후기 화면 및 개발용 일정표 코드 보존.

## 통합 시 정리한 부분

- 실제 인증과 멤버/일정 저장은 현재 NavGraph와 TravelRepository 경로를 유지한다. 개발 메뉴로 로그인 절차를 우회하지 않는다.
- 원격 저장소/ViewModel 기반 일정표는 `RepositoryTimelineScreen.kt`로 보존했다. 일반 여행 화면의 TimelineScreen은 일정 충돌 방지·추천 저장 경로를 사용한다. 개발용 투표 모달의 FakeVoteActions를 실서버 투표 완료로 간주하지 않는다.
- 숙소·교통 화면은 여행 화면의 버튼으로 연다. 입력한 체크인·체크아웃 표시는 현재 세션의 일정표에 전달하며, 숙소·교통 입력 자체를 서버에 영구 저장하는 기능을 새로 구현한 것은 아니다.
- 마이페이지/후기 화면의 예시 데이터는 팀원 원본 범위다. 계정/여행 실데이터 연결 완료로 표시하지 않는다.
- 원격의 누락된 랜딩 연결, 닫히지 않은 MemberRepository 클래스, 빠진 아이콘 리소스를 정리했다. 달력의 선택 날짜·인원을 실제 여행 생성에 전달한다.
- 테스트 폴더에서 운영 모델/화면을 다시 정의하던 복사본은 제거했다. 실제 테스트 클래스는 유지하며 운영 코드를 검사한다.
- Firebase 빌드 플러그인과 코루틴 연동을 유지했다. 팀원의 기존 이미지 라이브러리를 설치해 빌드를 확인한다. AGP/Gradle 버전을 올리지 않았다.

## 다른 개발 환경에서 실행

1. soyul 최신 코드를 받는다.
2. Firebase 프로젝트에 접근 가능한 계정으로 Android 앱 `com.example.mbtrip`의 `google-services.json`을 받아 `app/google-services.json`에 둔다.
3. Android SDK 경로는 개인 `local.properties`에서 설정하고 Gradle 동기화 후 실행한다.

Firebase 설정 파일, 개인 SDK/IDE 설정과 과거 서버 규칙 백업(`firebase/firestore.before-*.rules`)은 이번 커밋에 추가하지 않는다. 현재 관리 대상 서버 규칙은 `firebase/firestore.rules`다. 과거 검증 문서는 각 작업 당시의 기록이며 최신 통합 결과는 이 문서를 우선한다.

## 확인 결과

- 디버그 앱/테스트 APK 빌드 성공.
- 단위 테스트 94개 통과(원격 팀원 테스트 포함).
- 병합 후 집중 화면 검사 7개 통과: 달력과 여행 생성 입력 전달, 랜딩 로그인 진입, 로그아웃 및 계정 변경 화면 보호.
- 병합 후 전체 화면/실서버 검사 27개 실행은 가상 기기 연결 소실로 중단됐다. 전체 통과로 기록하지 않는다. 병합 전 전체 26개 통과 기록과 구분한다.
- 중단 당시 생성한 임시 여행의 소유자 UID와 검증용 표식을 확인하고 남은 임시 프로필/인증 계정을 정리했다. 복구용 임시 코드는 게시 대상에 포함하지 않는다.
- 실제 휴대전화 두 대의 전체 시나리오는 이후 수동 검증 범위다.
