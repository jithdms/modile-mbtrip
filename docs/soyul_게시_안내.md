# soyul 게시·실행 안내

2026-11-18 마감 변경의 게시 대상은 https://github.com/jithdms/modile-mbtrip 의 soyul이다. main 브랜치에는 커밋·푸시·병합하지 않는다. 커밋 식별자는 git log -1로 확인한다.

## 이번 변경

- 추천을 사용자 담당인 식당 23곳·카페 23곳, 총 46곳으로 한정.
- 누락 주소 40곳 추가, 거북섬 6곳 상세 위치 보완, 추천 화면 주소 표시 및 지도·신규 일정 주소 전달.
- 노을조개 근거를 현재 네이버 플레이스 주소로 정리, 조개포차·함돈의 매장 상세 근거 링크 보완.
- 실제 모바일 연결 검사에서 발견한 네이버 블로그 탭 이동 오류 수정.
- 독립 기기 동기화와 외부 앱 실행을 재현할 opt-in 검사, 두 기기 실행 스크립트 및 최신 문서 추가.

이전에 통합한 로그인·가입·초대·동행자·일정 저장 충돌 방지와 팀원 화면은 유지한다. 관광·체험 후보 제거는 기존 서버 일정을 일괄 삭제하는 작업이 아니다.

## 다른 개발 환경에서 실행

1. soyul 최신 코드를 받는다.
2. Firebase 프로젝트 권한이 있는 계정으로 Android 앱 com.example.mbtrip의 google-services.json을 받아 app/google-services.json에 둔다.
3. 개인 local.properties에 SDK 경로를 지정하고 Gradle Sync 후 실행한다. 기존 AGP/Gradle 버전을 유지한다.

Firebase 설정 파일, 개인 SDK·IDE 설정, 인증 정보, 과거 서버 규칙 백업과 테스트 실행 로그·임시 초대 코드는 게시 대상에 포함하지 않는다. 서버 규칙은 이번 마감 작업에서 다시 변경·게시하지 않았다.

## 통합 계약과 범위

- 사용자 진단: users/{uid}.jpScore, 현재 동행자: trips/{tripId}/members/{uid}, 일정: trips/{tripId}/blocks/{blockId}.
- 일정 저장은 scheduleVersion 충돌 검사를 함께 유지한다. 서버 거절을 우회하거나 규칙을 완화하지 않는다.
- 운영 화면의 추천 저장 경로는 TimelineScreen/TravelRepository다. 팀원의 RepositoryTimelineScreen 개발 경로와 투표 샘플을 실서버 완료 기능으로 혼동하지 않는다.
- 팀원 숙소·교통의 세션 전용 입력 및 프로필·후기의 예시 데이터 연결은 해당 담당자의 후속 범위다.
