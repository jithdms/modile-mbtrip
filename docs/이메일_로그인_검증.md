# 이메일 로그인 연결

작업 대상: 실제 Android 프로젝트의 soyul. main, 커밋, 푸시는 변경하지 않았다.

## 구현

- 가짜 중복 목록과 무조건 성공하던 로그인을 제거했다. 이메일/비밀번호 Firebase 인증이 성공하고 사용자 프로필 저장까지 마친 뒤 홈으로 이동한다.
- 가입 시 익명 사용자는 linkWithCredential로 이메일 인증을 연결해 UID와 기존 여행 소유권/멤버십/진단 데이터를 유지한다. 이미 사용 중인 이메일을 임의로 병합하지 않는다.
- 비밀번호는 메모리에서만 사용하며 인증 성공 후 지운다. 사용자 문서에는 이메일·비밀번호를 저장하지 않는다. 프로필은 merge 저장해 jpScore를 보존한다.
- 요청 중 입력과 중복 제출을 막는다. 인증 성공 뒤 프로필 저장이 실패하면 인증/가입을 반복하지 않고 프로필만 재시도한다.
- 계정 UID가 달라지면 기존 여행 상태를 재설정한다. UID가 같은 익명 계정 연결은 여행을 유지한다.
- 새 여행 생성 시 서버 사용자 프로필의 닉네임과 진단 점수를 먼저 읽는다.

## 검증 상태

- 앱/테스트 APK 빌드와 단위 테스트 74개 통과.
- Pixel_4a 전체 화면/여행 실서버 검사 실행: 실행 목록 16개 중 이메일 실서버 검사 1개는 별도 실행을 위해 건너뛰었고, 나머지 15개가 통과했다. 새 화면 테스트 3개, 빈 입력/잘못된 로그인 거절 2개, 기존 여행 실서버 권한·동시 저장 검증을 포함한다.
- 사용자 승인 후 Firebase 이메일/비밀번호 로그인을 활성화했다. 익명 로그인은 유지하고 이메일 링크 로그인은 활성화하지 않았다.
- 별도 이메일 실서버 검사 1개 통과. 익명 계정에 이메일 연결 시 UID 유지, 로그아웃/재로그인 시 같은 UID, 기존 여행 소유권/진단 27점 유지, 프로필 닉네임 저장, 잘못된 비밀번호 거절을 확인했다.
- 최종 실서버 로그: `RESULT stage=passed cleanupErrors=[]`. 임시 여행/멤버/사용자 프로필/인증 계정 정리 완료. 기본 앱 계정은 사용하거나 변경하지 않았다.

## 남은 범위

- 초대 코드 생성 및 안전한 참가 흐름은 별도 다음 단계다. 현재 여행 불러오기는 기존 멤버만 가능하다.
- 로그아웃, 비밀번호 재설정, 이메일 확인, 기존 익명 계정과 이미 가입된 다른 계정 사이 데이터 이관은 이번 구현 범위에 포함하지 않았다.
- 다른 기기에서 지난 여행을 자동으로 목록화하는 기능은 없다. 참여 여행 ID로 불러온다.
