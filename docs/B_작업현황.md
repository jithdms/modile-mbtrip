## 저장 경로·팀 연동 계약

- 사용자 진단: `users/{uid}`의 `jpScore`.
- 여행 동행자: `trips/{tripId}/members/{uid}`. 누락된 진단은 화면에 미진단으로 표시하고 자동 배분에서 차단한다.
- 일정: `trips/{tripId}/blocks/{blockId}`.
- 일정 필드는 팀 문서 형식 `startTime/endTime/type/place={name,lat,lng}/source=siheung`을 사용한다. 기존 `start/end/kind/place=문자열` 형식도 읽는다. 좌표·주소·삭제 제안 상태는 보존한다.
- 새 여행의 추가 필드: `ownerId`(생성자 UID), `scheduleVersion`(일정 저장 충돌 확인). 기존 문서에 소유자가 없으면 추측하지 않고 내보내기를 허용하지 않는다. 일정 버전은 모든 일정 작성자가 함께 갱신해야 신규 블록 동시 추가까지 일관되게 검사할 수 있다.
- 새 데이터는 샘플 여행 ID로 저장하지 않는다. Compose 미리보기에서만 기존 샘플 데이터 기본값을 사용할 수 있다.
- 현재 여행의 `startDate/endDate`로 여행 중 상태를 계산한다. 다른 여행까지 아우르는 계정 전체 여행 상태는 아니다.
- 프로필 사진은 멤버 문서의 HTTPS `photoUrl`을 읽는다. 링크 오류 시 이름 첫 글자로 대체한다. 사진 업로드/사용자 프로필 동기화 기능은 포함하지 않는다.
