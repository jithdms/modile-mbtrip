# 초대 코드 발급·여행 참가

작업일: 2026-11-18. 실제 Android 프로젝트 soyul에서 작업하며 main 수정·커밋·푸시는 하지 않는다.

## 사용하는 순서

1. 여행을 만든 사용자가 여행 화면에서 `새 초대 코드 발급`을 누른다.
2. `초대 코드 복사`를 눌러 동행자에게 직접 전달한다. 앱이 메시지를 자동 전송하지는 않는다.
3. 동행자는 로그인 후 홈의 `초대 코드로 참가`를 누르고 코드를 붙여 넣는다.
4. 서버가 참가를 승인하면 해당 여행 화면으로 이동한다. 기존 사용자 프로필의 닉네임과 진단 점수도 멤버 정보에 반영된다.

## 권한과 코드 수명

- 128비트 난수의 32자리 코드이며 한 번, 한 명만 사용할 수 있다. 앱 발급 시 12시간 후 만료되고 서버에서도 만료를 검사한다.
- 여행당 최신 코드 하나만 유효하다. 재발급 또는 `초대 취소`로 이전 코드를 취소한다. 한 명 참가 후 다른 사람을 초대하려면 새 코드를 발급한다.
- 코드 소지자는 여행 멤버 권한을 얻으므로 초대할 사람에게만 전달한다. 초대는 링크 자동 실행이나 짧은 숫자 코드가 아니다.
- 멤버 등록과 코드 사용 처리는 하나의 원자적 작업이다. 코드만 소비하거나 코드 사용 처리 없이 자기 멤버 문서를 만드는 것은 거절된다.
- 초대 문서 전체 목록과 비멤버의 여행 조회는 허용하지 않는다. 정확한 코드로 최소 정보(여행 ID·소유자 UID·만료·사용 상태)만 확인한다.
- 사용한 코드의 반복 참가와 내보낸 사용자의 같은 코드 재등록을 막는다. 동시 참가에는 한 명만 성공한다.
- 여행 인원 입력값은 계획 인원이다. 이번 단계에서는 강제 정원 제한을 추가하지 않았다.

## 구현 파일

- `travel/InviteCode.kt`: 난수 코드·입력 정규화.
- `travel/InviteRepository.kt`: 소유자 발급/취소, 프로필 기반 참가, 원자적 코드 소비.
- `travel/InviteUi.kt`: 발급·복사·취소와 참가 대화상자. 처리 중 중복 요청 차단 및 오류 재시도.
- `navigation/NavGraph.kt`, `ui/component/TripExampleScreen.kt`: 홈·현재 여행 진입 경로.
- `firebase/firestore.rules`: 소유자 발급, 코드 검증, 참가 권한 및 원자성 검사.

## 확인 상태

- 앱 및 테스트 APK 빌드 통과.
- 단위 테스트 76개 통과(초대 코드 검사 2개 포함).
- 초대 화면 검사 3개 통과(입력/오류 재시도, 중복 제출 차단, 발급/취소).
- 사용자 승인 후 2026-11-18 00:06(KST) 서버 규칙 게시 성공 확인. 게시 전 실제 서버 규칙은 `firebase/firestore.before-invites-2026-11-18.rules`에 별도 백업했다.
- 초대 실서버 검사 통과: 무단 멤버 등록/초대 전체 목록 조회/비소유자 발급/코드만 소비 차단, 정상 참가 및 프로필 점수·닉네임 반영, 이미 참여한 사용자의 재시도, 사용 코드 재사용·내보낸 사용자 재등록 차단, 재발급·취소·만료·동시 참가를 확인했다.
- 기존 여행 실서버 검사도 재실행하여 통과했다. 첫 전체 검사에서는 동시 저장이 1건만 성공했지만 패배한 요청의 예외를 최상위 타입만 검사하여 실패했다. 원인 예외 체인까지 검사하도록 보완했으며 재실행에서 stale-data guard의 IllegalArgumentException과 최종 통과를 확인했다. 첫 실패의 정확한 예외 체인은 당시 로그에 없어 확정하지 않았다.
- 서버 로그: 초대 `stage=passed cleanupErrors=[]`, 기존 여행 `stage=complete failure=null cleanupErrors=[]`. 임시 코드/여행/멤버/프로필/인증 계정 정리 완료.
- 최종 전체 검사 20개 통과, 실패/오류/건너뜀 0개. 이메일 계정 연결·재로그인, 기존 여행 서버 권한·동시 저장, 초대 서버 검증 및 모든 화면 검사를 함께 활성화해 재확인했다.

서버 규칙의 원자적 검증에는 Firebase 공식 문서의 getAfter 방식을 사용했다: https://firebase.google.com/docs/firestore/security/rules-conditions
