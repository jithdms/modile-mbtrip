# 로그아웃·로그인 유지·계정별 여행 복원

작업일: 2026-11-18. 실제 Android 프로젝트의 soyul에서 진행했다. main 수정·커밋·푸시는 없다.

## 사용자 흐름

- 로그인된 이메일 계정으로 앱 화면을 새로 구성하면 홈에서 시작한다.
- 홈 상단에 현재 계정과 `로그아웃`을 표시한다. 확인 후 로그아웃하면 로그인 화면으로 이동한다.
- 로그아웃 시 이전 화면 기록을 비워 뒤로가기로 여행/진단 화면에 돌아가지 않도록 한다. 로그인하지 않은 상태의 보호 화면 진입도 로그인으로 돌려보낸다.
- 여행 생성/불러오기 중에는 로그아웃 버튼을 비활성화한다. 계정 UID가 바뀌면 이전 계정의 화면 요청, 입력, 오류와 구독을 초기화한다. 이미 서버에 완료된 저장을 되돌리는 기능은 아니다.
- 익명 계정은 로그아웃으로 접근 수단을 잃지 않도록 먼저 이메일 계정을 연결하게 한다.
- 최근 여행을 UID별로 따로 기억한다. A 계정 → B 계정 → A 계정으로 전환해도 A의 최근 여행을 복원한다. 진단 점수 캐시도 현재 UID 값만 읽는다.
- 이전 단일 저장 형식은 저장 UID가 현재 계정과 같을 때 복원한다. 서버 여행/멤버 문서는 복사·이관·삭제하지 않는다.

## 구현 파일

- auth/AccountSession.kt: Firebase 계정 상태 관찰, 로그아웃, 익명 계정 보호.
- auth/AccountSessionBar.kt: 현재 계정 표시·로그아웃 확인·이메일 연결 안내.
- navigation/NavGraph.kt: 로그인 유지 진입, UID 변경 초기화, 보호 화면 접근 제어.
- ui/screens/LoginScreen.kt: 로그인 성공 후 이전 화면 기록 제거.
- travel/TravelRepository.kt: 계정별 최근 여행 저장 및 이전 형식 복원.

## 검증

- 단위 테스트 76개 통과.
- SessionUiInstrumentedTest: 로그인 유지 홈 진입, 로그아웃 취소·확정과 화면 기록 삭제, 진단 화면에서 세션 종료, 계정 변경 시 이전 초대 입력 제거, 익명 계정 연결 안내, 미로그인 보호 화면 진입 차단을 검사한다(5개 테스트).
- SessionLiveInstrumentedTest: 별도 FirebaseApp의 임시 두 이메일 계정으로 A/B/A 전환, 각 계정 여행·진단 점수 복원, 다른 계정의 여행 접근 거부, 로그아웃 시 캐시 비노출, 이전 저장 형식 복원을 검사한다.
- 임시 두 계정의 서버 여행/멤버/프로필/인증 계정과 로컬 테스트 저장소는 finally에서 정리한다. 기본 앱 계정은 사용하거나 변경하지 않는다.
- 전체 화면/실서버 검사 26개 통과, 실패/오류/건너뜀 0개. 사용자의 재검증 요청에 따른 반복 실행도 통과했다. 계정 전환 로그는 RESULT stage=passed cleanupErrors=[]이며 기존 이메일 로그인·초대·여행 권한 검사도 함께 통과했다.

이번 자동 검증은 새 화면 구성과 저장소 재생성으로 복원을 확인했다. 실제 휴대전화 두 대에서 앱 프로세스를 강제 종료한 뒤 다시 여는 수동 시나리오는 별도 확인 범위다.

Firebase 설정과 서버 규칙 변경은 없으며, 비밀번호 재설정/이메일 확인/계정 간 데이터 이관은 포함하지 않았다.
